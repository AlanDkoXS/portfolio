# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Personal portfolio site (alanquintana.pro), plain static HTML/CSS/vanilla JS. No bundler, no package manager, no tests, no linter config committed (`package.json`, `eslint.config.mjs`, `.prettierrc` are gitignored). Deployed on Netlify straight from the repo root. The only "build" is the zero-dependency i18n generator below, whose output is committed.

## i18n generator

```sh
node scripts/build-i18n.mjs   # run after editing index.html, translations.js or any CSS partial
```

Rewrites `index.html` in place with the English texts and generates `es/index.html` (Spanish, committed, never edit by hand). Idempotent; fails listing any missing translation keys. It also bundles the CSS: `assets/css/main.src.css` (the list of `@import`s) → `assets/css/main.css` (one generated file, committed, never edit by hand), so pages load a single stylesheet instead of a request chain. `main.css` is minified by `scripts/lib/css-bundle.mjs` with a deliberately conservative minifier (comments dropped, whitespace collapsed and removed only next to `{ } ; ,` and after `:`; strings, `url()`, custom property values and values using `var()`/`env()`/`attr()` copied verbatim, at-rule preludes keep their spaces): the browser must parse it into exactly the same CSSOM as the unminified bundle, so check any change to the minifier that way. It also fails if a page's `<link rel="modulepreload">` list doesn't match the modules it imports up front (`scripts/lib/module-preloads.mjs`, see Architecture).

It also generates the **project case-study pages** from `scripts/data/projects.mjs` (content in EN/ES, facts taken from each repo) with the template in `scripts/lib/project-page.mjs`: `projects/<slug>/index.html` (en) and `es/proyectos/<slug>/index.html` (es), committed, never edit by hand. They reuse the home header/footer (section links rewritten to `/#…` or `/es/#…`), carry canonical/hreflang/OG/JSON-LD (SoftwareApplication + BreadcrumbList), and the generator rewrites the `<!-- projects:start/end -->` block of `sitemap.xml`. To add a project: add its entry to `projects.mjs` (same order as the home cards), its screenshots (`project_img/<image>.webp` 560×700 home card, `mobile/<image>.webp` 390×844 phone screenshot for the case page, `desktop/<image>.webp` 1280×800, `og/<image>.jpg` 1200×630, plus `-dark` variants if it has its own dark mode), a card in `index.html` and its `projectCase` hrefs in `translations.js`.

`build-i18n.mjs` only orchestrates; each step is a module in `scripts/lib/`: `render.mjs` (i18n render + missing-key check), `css-bundle.mjs` (bundle + minifier), `skills-sprite.mjs`, `designs-section.mjs`, `theme-head.mjs`, `project-page.mjs`, `sitemap.mjs` (pure function), `llms.mjs` and `module-preloads.mjs`. Every build script shares `site.mjs` (`ROOT`, `SITE`, `LANGS`, `homePath`/`projectPath`, `CV_FILES`, `fail`, `withTmpDir`) and `html.mjs` (`escapeText`/`escapeAttr`, always imported under those names): use them instead of resolving the repo root, hardcoding the domain, the language list or the CV file names, or writing another escaper. Texts the project pages share with the home page (nav and demo/code labels) are read from `translations.js`, not repeated in the template.

## Icons (Boxicons subset)

```sh
node scripts/build-icons.mjs  # run after using a bx-* icon that wasn't used before
```

Scans `index.html`, `resume.html`, `scripts/lib`, `scripts/data` and `assets/js` for `bx-*`/`bxs-*`/`bxl-*` classes and, from the full Boxicons in `scripts/vendor/boxicons/`, writes `assets/css/vendor/boxicons.min.css` (only those classes) and a subset `assets/fonts/boxicons/boxicons.woff2` (~3 KB instead of 116 KB) with `pyftsubset` via `uvx` (fonttools). Then run `build-i18n.mjs` so the CSS reaches `main.css`. Don't build icon class names dynamically (`'bx-' + name`): the scan wouldn't find them.

## Dribbble shots (Designs section)

```sh
DRIBBBLE_TOKEN=xxxx node scripts/build-dribbble.mjs   # DRIBBBLE_LIMIT=12 optional
```

Fetches the user's shots from the Dribbble API v2 (access token of a Dribbble app, never committed nor sent to the browser), converts each cover to `assets/img/dribbble/<id>.webp` (800×600, first frame if animated, ImageMagick `magick`), writes `scripts/data/dribbble.json` (committed) and runs `build-i18n.mjs`, which renders the `#designs` section into the `<!-- dribbble:start/end -->` block of `index.html` (template in `scripts/lib/designs-section.mjs`, styles in `sections/_designs.css`: title and description at the start like every section, centered grid on desktop, horizontal scroll-snap row on mobile). Without shots the block stays empty and the section isn't shown.

## CV (PDF) generator

```sh
node scripts/build-cv.mjs   # run after editing scripts/cv/data.mjs
```

Builds `assets/docs/[ENG] Alan Quintana.pdf`, `[ESP] Alan Quintana.pdf` and `resume.pdf` (EN page 1 + ES page 2, shown by `/resume`) from `scripts/cv/data.mjs`, printing an HTML template (`scripts/lib/cv-page.mjs`) with the system Chromium and joining with `pdfunite` (poppler). Each CV must fit one Letter page; the script fails if one overflows. The email is per language (`hello@` EN, `hola@` ES; same inbox). Experience lists the Aniwa (beaniwa.com) client sites.

## Running locally

JS is loaded as native ES modules with absolute imports (e.g. `/assets/js/languages/translations.js`), so opening `index.html` via `file://` won't work. Serve the repo root over HTTP:

```sh
python -m http.server 8000   # then open http://localhost:8000
```

`_redirects` is Netlify-specific (`/resume.html` → `/resume`, and Netlify serves `resume.html` at `/resume`), so the clean `/resume` URL only works on Netlify; use `/resume.html` locally. The home's CV links point straight at `/resume?lang=…` (no 301 on Netlify), so they 404 under `python -m http.server`: open `/resume.html?lang=…` by hand there.

## Architecture

**Two pages, shared modules.**
- `index.html` loads `assets/js/main.js`, which orchestrates everything: it initializes the helpers from `assets/js/helpers/` in a fixed order inside `initialize()` (external scripts → dark mode → UI components → visual effects → functionalities; each group isolated, an error skips only the rest of its group). New features are added as a helper module and wired in there. Only what the first screen needs is imported up front; the rest is imported on demand with `import()` through `loadStep()`/`onIdle()` from `helpers/lazy.js` (a failed download or start is reported under the step's name, like the groups): the console logo on idle; `parallax.js` + `profile-parallax.js` (which import `tilt.js` themselves, only on touch devices) once the hero is shown (`heroReady` from `loader.js`) and the browser is idle (≤ 500 ms), never with reduced motion; `contact-form.js` (sending, EmailJS) when `#contact` first gets within 400px of the viewport (the `onNear` callback of `project-covers.js`, the same signal that loads the covers) or on the first `focusin`/`pointerdown` in the form, with a submit held until it has started (the form has no action) and resent with `requestSubmit()`; the field validation on blur (`form-validation.js`) stays eager so it never waits for a download; `snow-effect.js` only in season (see Seasonal effect). `card-carousel.js` stays eager on purpose: laying the cards out after the page has been painted once changes how Chrome rasterizes the scaled side cards (anti-aliasing), so the screenshots would no longer match. Every page preloads (`<link rel="modulepreload">`) exactly the modules it imports up front, minus the ones its own `<script type="module">` names (they're discovered at once), and never the on-demand ones; the generator fails when a list drifts, so update it when a helper's static imports change.
- `resume.html` does **not** load `main.js`; its inline `<script type="module">` imports only the helpers it needs (`resume-fab.js`, `pdf-loader.js` and `common.js`, whose `initCommon()` runs the shared steps: language, dark mode, lamp, menu, footer year, snow, GTM; the project template does the same plus `parallax.js`). `resume-fab.js` reads no layout on scroll: an IntersectionObserver on the footer, a ResizeObserver on the body and the PDF/resize hooks cache the footer's position and the button's `bottom`, and a rAF-throttled scroll handler only does arithmetic with `scrollY`. Shared helpers like `language-switcher.js` run on both pages, so they must tolerate missing DOM elements (they early-return when selectors don't match). The resume has the same navbar as the home (same section links, pointing to `/#…` or `/es/#…` through `resumePage.*Href`, none marked active; flag buttons and caption in the mobile menu), the logo in Poppins, and a "Back to home" ghost button above the CV (`.project-back.resume-back`, same as the case pages). It renders only the active language's page of `/assets/docs/resume.pdf` (page 1 = EN, page 2 = ES, swapped on `languageChange`) with pdf.js (ES module imported from cdnjs by `pdf-loader.js`, preloaded with `modulepreload`; keep the version in sync with `PDFJS_VERSION`). On mobile (`width < 600px`) the CV takes as much of the screen as it can (thin side margins, less space above) and the download FAB is `position: fixed` over the blank bottom-right corner of the CV page as seen at the top of the page (or the bottom of the screen if the CV is taller), anchored by its right side so it expands to the left; it stays put while the CV scrolls under it, rising only to stay above the footer, and expands with its label once the page is scrolled and the button is on screen. On desktop it's fixed bottom right (centered in the free space below the CV when there is some) and pushed up above the footer. The FAB (`.resume-fab__button`) is a regular `.btn`: same font size, 1.25em icon, 8px gap and padding; square with the icon when collapsed, as tall as a text button in both states (`1lh` + padding + border), margin 0 (so the 14px `FAB_INSET` is the visible gap on both edges of the CV corner); `.resume-fab` aligns it to its right edge, and its width eases only without reduced motion and where `auto` can be interpolated (`interpolate-size`), instant elsewhere. The FAB opens a dialog whose `data-cv` buttons download `[ENG]`/`[ESP] Alan Quintana.pdf` (listeners in the inline module; no inline `onclick` handlers).

**i18n (EN/ES).** `assets/js/languages/translations.js` is the single source of text (`{ key: { en, es } }`; nested ones like `contactForm`, `resumePage`, `meta` hold an object per language). Markup marks translatable content with `data-i18n="key.path"` (element text) and `data-i18n-attr="attr:key;attr2:key2"` (attributes, e.g. meta tags, canonical, hrefs). Key paths put the language after the first segment (`contactForm.name` → `contactForm[lang].name`, `skillsTags.2` → `skillsTags[lang][2]`), resolved by `assets/js/languages/translate.js`, shared by the generator and the browser. Elements with `data-i18n` must contain only text — their content is replaced wholesale.
- Home page = **URL mode**: `/` (en) and `/es/` (es) are separate static pages with `canonical`/`hreflang` links. `language-switcher.js` takes the language from `<html lang>`; the `#language-toggle` stores the choice in `localStorage.lang`. On the home it switches in place (texts and translated hrefs swapped in the DOM, no page load) and rewrites the URL to the other version with `history.replaceState` (keeping the hash), so reloads and shared links stay in the chosen language; on the case pages it navigates to the other version (prerendered on intent, see Loader & greeting). An inline script in `<head>` sends Spanish-browser visitors from `/` to `/es/` (and from the English project pages to `/es/proyectos/<slug>/`, same script in `project-page.mjs`) unless `localStorage.lang` says otherwise. There is no reverse redirect from `/es/` (shared Spanish links stay Spanish and crawlers, which browse in English, can still index `/es/`).
- Resume page = **in-place mode** (no hreflang alternates): language from the `?lang=` the home's CV links carry (`resumeHref` in translations, so the CV follows the page it was opened from; it's stored and stripped from the URL), else `localStorage.lang`, else the browser; texts swapped in the DOM.
- To add text: add the key to `translations.js`, put `data-i18n` on the element in `index.html` (or `resume.html`), run the generator.
- A `languageChange` CustomEvent is dispatched so other modules (e.g. form validation in `contact-form.js`) can react.
- All asset URLs in `index.html` must be absolute (`/assets/...`) because the same markup is served from `/es/`.

**Responsive home text.** On widths ≥600px the home description is merged with the about description (and the About section is hidden via CSS). This lives in `handleResponsiveContent` in `language-switcher.js` so it uses the active language.

**Hero parallax.** `parallax.js` (background SVG layers `.background--back/--middle/--front`) and `profile-parallax.js` (profile picture layers) follow the mouse on desktop and device tilt on touch devices (`(pointer: coarse)`). Both (and the lamp) get tilt from `tilt.js` (imported on demand, only on touch devices), ONE shared source per page (one `deviceorientation` listener, one `requestAnimationFrame` loop) with subscribers (`subscribeTilt(onFrame, { active, follow })` → `setActive()`); it handles the iOS `DeviceOrientationEvent.requestPermission()` gesture, makes tilt relative to how the phone is held, clamps/smooths it once per frame, and recenters after 2s without motion. The loop only runs while a subscriber is active (and not while the page is hidden): the background while in tilt mode, the portrait while it's on screen (IntersectionObserver), the lamp while it's visible (from 600px, or inside the open mobile menu). The lamp subscribes with `follow`, so its pendulum keeps integrating the frames the loop runs for the others; when the loop restarts after a pause it replays the missed frames (≤ 300) with the readings each frame would have seen, so the values are the same as if it had kept running (readings older than those frames are folded as they age, so the log stays at ~5 s). Mobile layers are driven from that loop, so CSS transitions on those elements are disabled while in tilt mode.

**Profile sprite.** `.home__image-sprite` animates `profile_sprite.webp` (20 frames of 750×750 in a 15000×750 strip, sRGB, no ICC profile; `profile_sprite-1x.webp` is the same strip at half size, picked by `image-set()` on 1x screens: 0 original gaze, 1–10 turn to look, 11 looking, 12–16 blink, 17–19 quick return) with `background-size: 2000% 100%` and percentage `background-position` (frame i = i/19 × 100%), so frames stay aligned at any rendered size. The `profile-look` keyframes in `_home.css` play a hand-timed sequence once `html.hero-ready` is set (turn at 1s, one blink at 2s, a double blink at 7s, turn back at 15s with frames 9→0; loops forever every 22.45s, so it turns again 8s after the gaze is back) using `step-end` so each keyframe holds its frame. Keep the 2000% / 19 divisor in sync if the frame count changes.

**External services** are loaded dynamically by helpers rather than via `<script>` tags, and never on the critical path (nothing awaits them): EmailJS (`email-js.js`, memoized; `contact-form.js`, itself imported on demand, loads it on the first `focusin`/`pointerdown` in the form and awaits it before sending; it silently drops submissions that fill the hidden `#website` honeypot field) and Google Tag Manager (`google-tag-manager.js`, container `GTM-MRJGJ8NP`; GA4 is configured inside GTM): injected after idle or the first interaction, never on localhost and only once a prerendered page is activated.

**CSS.** `assets/css/main.src.css` is just `@import`s of partials (bundled into `main.css` by the generator; URLs inside partials must be absolute) organized as `base/` (variables, base), `layout/` (header, footer, buttons, modal, loader, background), and `sections/` (one file per page section, including `_resume.css`). Class naming follows BEM (`block__element--modifier`). Theme (`helpers/auto-dark-mode.js`): dark if the system is in dark mode; otherwise time-based (visitor's local time; light is every device's default, so it can't be told apart from a choice): dark from 18:00 to 6:00, light otherwise, switching at the exact hour even with the page open (timer + re-check on `visibilitychange`). The toggle/lamp stores an override in `localStorage.theme` + `themeUntil` that lasts only until the next switch (toggling back to the scheduled theme removes it). The theme is written to `<meta name="color-scheme">`; an inline `<head>` script applies it before first paint (no flash). That script lives in the `<!-- theme:start/end -->` block of `index.html` (single source, together with the color-scheme meta; the comment above the block and the text-scale meta are not part of it, each page keeps its own): edit it only there and run `build-i18n.mjs`, which copies the block into the same markers of `resume.html` and, without markers, into `es/index.html` and the project pages (it fails before writing anything if a marker is missing in `index.html` or `resume.html`); keep its 18/6 hours in sync with `auto-dark-mode.js`; without JS the meta stays `light dark` and the system scheme is used. CSS maps that meta to `color-scheme` and to a `--color-scheme` custom property in `_variables.css`. Colors are `light-dark()` tokens: both schemes are teal (light = `#00303d`, dark = deeper `#001a23`); the main color (`--gold-main`) is gold `#f3ce3a` in light and pale yellow `#f2e2a0` in dark, and textures follow (button/tag grain and inset shadow are dark gold in light, warm yellow-gray in dark; non-color values such as grain images, masks and the skills icon filter `--icon-grain` are switched per scheme in the `:root` color-scheme block of `_variables.css`, since `light-dark()` only takes colors). In dark mode the button texture sits bottom-left (the lamp light comes from the top right); use the semantic tokens (`--primary-color`, `--accent-color`, `--accent-ink`, `--surface-color`, `--border-color`, `--shadow-color`, …) instead of hex values. Non-color light/dark branches use `@container style(--color-scheme: …)` as non-critical overrides. Buttons: `.btn--primary` (solid gold, an explicit alias of the default `.btn` look) for main actions, `.btn--ghost` (outline) only for secondary ones like the contact form submit. Footer and project cards use the same tokens as the page (no fixed gold).

**Design tokens.** Sizes, spacing and shadows also come from `_variables.css`; use them instead of new literals:
- Layout: `--container-width` (1024px, every block's max width with its side padding: grid container, section title, Designs, carousel arrows, case CTA, lamp margin); `--page-top-offset` (top of the Back button of the case pages and the resume: header + .75rem on phones, the compact value that leaves the CV its room, header + 1.75rem from 600px; set in `_variables.css`, no per-page override).
- Spacing scale `--space-1` … `--space-16` (.25/.5/.75/1/1.25/1.5/2/2.5/3/4rem): `--space-2` for icon rows, `--space-3` for lists and paragraphs; `--space-title` (.75rem, heading → content: section titles, every h3, case h2, contact, hero), `--surface-padding` (3rem 1.5rem: contact form on mobile and case CTA). Buttons keep `--button-padding` (.8rem).
- Type: headings are `--title-scale` (1.5) × `--title-font-size`; every h3 (Skills group titles, Soft Skills, contact form title, footer columns, case pages) is one rule in `_base.css`: `--h3-size` (1.25 × `--title-font-size`, resolved on `:root` so the case pages' own title scale doesn't change it: 22.4px on phones, 29px at 1440, h2 26.9/34.8), Outfit 700, line-height `normal`, margin `0 0 --space-title` (the case-page h3 adds `--space-6` above; the Development Tools header carries that bottom margin so the pause button stays centred). The accordion summaries' h3s are button labels (`font: inherit`) and the project card titles keep their own size. `--line-height-body` (1.5 on `body`); headings, buttons (`.btn`, card buttons, stack tags), the header/menu, the loader, the hero and About on mobile keep `normal` (their first-screen fit is tuned to it). `--btn-font-size` (`clamp(.9rem, .8rem + .4vw, 1.05rem)`) on every `.btn`, except the mobile hero buttons (they inherit the page size: the 360x640 first screen is tuned to them), the Back button (`--btn-small-font-size`, .875rem) and the case-page pager on phones (.85rem with less side padding, so "Siguiente ›" fits half a screen).
- Surfaces: two levels on purpose. Raised (contact form, case CTA): `--surface-raised-bg` (`--bg-color-buttons`), no border, `--shadow-soft-md`. Card (dialogs, Dribbble cards): `--surface-card-bg` (`--surface-color`) with `--surface-card-border` (1px `--border-color`).
- Radii: `--border-radius-xs` (2px: flags, list bullets) / `-small` (.25rem) / `-default` (.5rem) / `-large` (1rem); the Soft Skills bricks keep a deliberate 3px.
- Shadows: soft `--shadow-soft-sm/md/lg` (Dribbble cards; form, CTA, hovered card; dialogs, CV page); hard lengths `--hard-offset-sm` / `--hard-offset` / `--hard-offset-lg` (3/4/6px; `--btn-offset` reads them) in `--btn-ink-color`, or `--ink-on-dark` (black) on the always-dark card faces.
- Focus: `--focus-ring` with `--focus-offset` (4px, shadowed buttons and fields) or `--focus-offset-flat` (2px, flat controls).
- Icons: `--icon-btn-size` / `--icon-btn-glyph` (44px / 24px caps) for the icon-only buttons (marquee pause, carousel arrows, modal close, burger); `--social-icon-size` (1.5rem) for the desktop hero and footer social links (the mobile hero keeps 34px).

**Seasonal effect.** Snow only falls Dec 12 – Jan 6 (`isSnowSeason()` in `helpers/motion.js`, the single source of the rule) and never with reduced motion: the `snow` step of `common.js` only imports `snow-effect.js` then. It's removed on `pagehide` and started again on `pageshow` when the page comes back from the back/forward cache (no `beforeunload`/`unload` listeners anywhere: they can keep pages out of that cache). Each flake is replaced by a new random one (position, speed, opacity) on its `animationiteration` (one delegated listener; nothing is measured).

**Motion & robustness.** Decorative motion (parallax, tilt, snow, sprite, greeting typing, smooth scroll, card flip, hover drift) only runs when the user has no reduced-motion preference: JS effects check `prefersReducedMotion()` from `helpers/motion.js`; CSS opts in with `@media (prefers-reduced-motion: no-preference)`. Content must be visible without JS: section entry and the header reveal are scroll-driven CSS animations behind `@supports`. Section entry (`layout/_section.css`) fades in an explicit list of small blocks (titles, paragraphs, accordions, cards, form…) over a fixed `animation-range: entry 0% entry 240px`, so it's visible while scrolling regardless of block height; add new blocks to that list instead of animating whole sections; `project-covers.js` only lazy-loads project images (and tells `main.js` when `#contact` gets near, to import the form). Page-to-page navigations use a cross-document `@view-transition`.

**Project covers.** `assets/img/project_img/*.webp` are 560×700 (4:5, 2× the card) mobile screenshots of each live project, set in `_projects.css` by `nth-of-type` (card order matters). Projects with their own dark mode (CRUD, Traktl) also have `*-dark.webp`, swapped via `@container style(--color-scheme: dark)`. Don't set covers inline from JS, or the dark override stops working. They're lazy without JS-set URLs: every cover rule is prefixed with `:is(html:not(.js), .projects.is-near)` and `project-covers.js` adds `.is-near` to `#projects` when it gets within 400px of the viewport (keep the same prefix on new cover rules, including the dark ones, so specificity stays equal).

**Projects carousel** (`helpers/card-carousel.js`, started with the page): arrow buttons, arrow keys on the controller link and dragging with Pointer Events (mouse/pen always drag; touch locks to an axis after 4px, horizontal drags and vertical ones are left to the page scroll, `touch-action: pan-y`; a quick short swipe flicks one card). The drag follows the pointer through window listeners, not `setPointerCapture` (that would retarget the click to the carousel and break the cards' links). Sizes (container/card width, root font size) are read once (ResizeObserver, start of a gesture, navigation), never per move, and the per-move style writes are batched in one `requestAnimationFrame`; a new container width lays the cards out again in their initial slots.

**Skills section.** `#skills` starts with Development Tools as an infinite left-to-right row (`.skills__group--marquee`): its `.skills__group-header` puts the title centered and the `.skills__motion-toggle` pause button on the right (WCAG 2.2.2, `helpers/skills-marquee.js`, hidden with reduced motion). `.skills__track` holds 4 copies of the `<ul class="skills__list">` (only the first is accessible, the rest `aria-hidden`) and animates `translate: -50% → 0` over `--marquee-duration`; when adding a dev tool, add it to all 4 copies. Design, Frontend and Backend are native `<details class="skills__accordion">` (work without JS): the `<summary>` reuses `.btn .btn--ghost`, the panel `.skills__grid` is a static icon grid in a box with the same outline + hard shadow; Soft Skills are a brick wall (6-column grid, bricks span 2, second course offset by half a brick with decorative half bricks from the container's `::before`/`::after`); height animates via `::details-content` + `interpolate-size` where supported. Icons are SVG `<symbol>`s, one source file per tech in `assets/img/skills/`, merged by `build-i18n.mjs` into the generated sprite `assets/img/skills.svg` (one request; the markup uses `<use href="/assets/img/skills.svg?v=<hash>#iconX">`, the generator rewrites the `?v=` content hash (so a cached old sprite never hides new icons) and fails on unknown ids; optimize new icon files first with `npx svgo --config scripts/svgo.config.mjs <file>`, which keeps ids and hidden elements) (newer ones from Simple Icons, CC0) and get a grainy inner shadow from every edge inward via `filter: url(#grain-inset)` (inline SVG filter at the top of `<body>` in `index.html`).

**Fonts.** Text follows the system text size (all sizes in rem; `<meta name="text-scale" content="scale">` for Android/Chrome, `font: -apple-system-body` on `html` for iOS Dynamic Type; never set a px root font-size). On mobile the hero is one screen tall: text takes what it needs and the portrait row (`minmax(7rem, 1fr)`) shrinks to the leftover space (portrait capped at `min(90vw, 370px)`); About is centered under the navbar with a portrait capped by `svh`. Icons and button paddings use px caps so they don't grow with text. Text uses DM Sans (`--primary-font`, variable 100–1000 with opsz axis), headings (`h1`–`h6`, `.project-pager__title`) use Outfit (`--title-font`, variable 100–900), and the logo name and loader are **always Poppins** (`--brand-font`, weights 200/300/500/600, latin only). Always self-hosted (downloaded woff2, never Google Fonts / unpkg): woff2 in `assets/fonts/{dm-sans,outfit,poppins}/` declared in `base/_fonts.css`, and Boxicons (subset, see Icons above) in `assets/fonts/boxicons/` with its CSS in `assets/css/vendor/boxicons.min.css`, bundled at the end of `main.css`. Pages preload only what their first screen shows: the home preloads DM Sans, Outfit and Boxicons (hero) and Poppins 300 (the logo: hidden at the top until the header is revealed, but laid out from the first frame; with low priority its late swap changed the rendering); the loader's Poppins 200/600 are preloaded by the `<head>` script only on the first visit of the session; the project pages preload DM Sans, Outfit, Poppins 300 and 600 (logo, visible at the top) and Boxicons; the resume preloads DM Sans and Boxicons, Outfit with `fetchpriority="low"` (only below the fold) and no Poppins (only its logo uses it; it swaps in). Header flag images are not lazy (above the fold; the mobile menu's `.lang-switch` flags are the same files, not lazy either); the lamp's idle/lit images get `fetchpriority="low"` (hidden on mobile until the menu opens), its hover/pressed ones stay lazy. SVG `<use>` takes `href` (SVG2), not `xlink:href`.

**Hero images.** The LCP is the portrait background `profile_bg.svg` (a CSS background, so `index.html` preloads it with `fetchpriority="high"`). Its noise texture is embedded as a small WebP (500 px, 4 tones) because an SVG used as a CSS image can't load external files. The page grain (`.background--grain`) is a seamless 256×256 tile of independent random dots (`bgGrain-tile.webp`, same density as the original grain; an SVG noise was too fine to see on phones), fixed from the top of the viewport (so no grainless band shows while the navbar is hidden), fading out from just below the navbar; its long top-to-bottom fade lives in the `--grain-fade` mask.

**Icon font.** Boxicons opts out in `_base.css`, otherwise every icon renders ~55% of its size.

**Hanging lamp** (`helpers/lamp.js`, `layout/_lamp.css`): theme switch that hangs below the navbar (desktop: centered in the right margin, replaces the moon/sun toggle; mobile: only shown inside the open hamburger menu, which has no moon/sun; it drops in with a bounce once the panel has opened, left of the close X). Lit = dark mode. States: hover (`lamp__over`), pressing (`lamp--pulling`, chain pulled), on (`lamp__on`); images in `assets/img/lamp_button/`. A mouse/touch click blurs it (no focus ring after pressing a key). On touch devices it swings like a pendulum with the gyroscope (shared `tilt.js` source, imported only there, + spring in `lamp.js`, angle in `--lamp-tilt` on `<html>`, written only while the lamp is visible). It moves as a double pendulum: the whole `.lamp` (cord and lamp) rotates from the top of the screen (`lamp-cord-swing`, small angles, half of `--lamp-tilt`) and the lamp image turns a bit more at the cord–lamp joint (`lamp-swing`, 0.12s behind, 0.6 × `--lamp-tilt`); hover, a click and the mobile drop play both (the drop keeps its bungee running alongside), and `.lamp--swing` is removed when the cord animation, the last one, ends. The swing after a click or the mobile drop restarts the CSS `lamp-swing` animation by toggling `.lamp--swing` and rewinding the running animation with the Web Animations API (`getAnimations()`, `currentTime = 0`), no forced layout. The swing after the mobile drop still starts from the header's class MutationObserver plus a timer (0.25s + 42% of the 1.1s bungee): with reduced motion there is no bungee animation to listen to, and the class history must stay the same. In dark mode the open mobile menu gets a halo of the lamp's light color (`.navbar__menu::before` in `_header.css`): it appears with the lamp, follows its bungee/swing and rotates with `--lamp-tilt`.

**Mobile menu** (`helpers/nav-menu.js`, wired on home, resume and project pages): `.navbar__burger` toggles `.menu-open` on `.header` (with `aria-expanded`); the `#nav` panel drops just below the bar with the same subtle links as desktop and the burger morphs into an X. Closes on link click, Escape, outside click or when crossing to desktop. Without JS, `#nav:target` still opens it. Below the section links, after a divider, a "Change language" / "Cambiar idioma" caption (`.navbar__toggles-caption`, `navLanguage`) and two flag ghost buttons (`.lang-switch` inside the language toggle's label, mobile only; desktop keeps the single flag): desaturated, subtle grain, the primary buttons' outer hard shadow; the current language is pressed and darker and ignores taps (the label has `pointer-events: none`, only the other flag toggles the checkbox); in dark mode an inner grain shadow sits bottom-left, away from the lamp. Only the desktop flag (`.navbar__language-flags img`) runs the switch animation; the flag buttons stay visible while the language changes. The resume and the project pages carry the same markup (the project pages copy the home header).

**Loader & greeting.** The loader (letters falling into the name) shows only on the first load of the session (`sessionStorage['aq-loaded']`, `.skip-loader` set in `<head>`) and never while prerendering. When it leaves, `html.hero-ready` is set and `helpers/typing.js` types the greeting letter by letter with a blinking underscore caret. On the case pages the other language is prerendered with speculation rules so switching is near instant: `language-switcher.js` inserts the rule on the first `pointerenter`/`focusin`/`touchstart` on the language toggle (intent), not on every visit (the home switches in place, so it prerenders nothing). On every URL-mode page (home and project pages) it also adds a speculation-rules prefetch with moderate eagerness (pointer resting on a link, or pressed) for `/resume*` and the project pages (`/projects/*`, `/es/proyectos/*`), instead of an always-on `<link rel="prefetch">`.

**Hero copy (desktop).** `homeDescription` (intro; `*text*` in a translation renders as `<strong>`, in the generator and in `language-switcher.js`) + `heroLines` (7 phrases of exactly 7 words, plain language for non-technical readers), rendered as one paragraph by `handleResponsiveContent`. Keep the 7×7 rule when editing.

**Section focus.** Sections carry `tabindex="-1"` so hash jumps move focus; `section[tabindex='-1']:focus { outline: none }` in `_base.css` hides the focus ring (Chrome Android drew white lines around the hero after `/es/#home`).

**Dialogs.** Native `<dialog>` opened with `showModal()`, `closedby="any"` for light dismiss (Safari fallback in `helpers/dialog.js`), named via `aria-labelledby`. The dialog box is the card; the dim/blur lives in `::backdrop`.

## SEO files

`sitemap.xml` (with `xhtml:link` hreflang alternates for `/`, `/es/` and the generated project pages), `robots.txt`, and the JSON-LD block in `index.html`'s `<head>` should be kept in sync with page/URL changes. `llms.txt` and `llms-full.txt` (profile for AI search engines and agents, EN + ES, with FAQ) are generated by `build-i18n.mjs` from `scripts/data/profile.mjs`, `projects.mjs` and `scripts/cv/data.mjs`; never edit them by hand. `robots.txt` explicitly allows AI crawlers and points to them. The JSON-LD block is marked `data-i18n-jsonld`; the generator merges `translations.meta[lang].jsonLd` into it.

## Netlify

`_redirects` (`/resume.html` → `/resume`) and `_headers` (security headers + moderate `Cache-Control` with `stale-while-revalidate`, since asset names aren't fingerprinted; replacing an image keeps its old version cached up to a day).

`reset-to-home.js` forces `#home` only on a manual reload (assigning `location.hash`, which jumps to the top) or when there's no hash (`history.replaceState`: the page is already at the top, so no history entry and no smooth scroll), so shared links like `/es/#contact` keep working.
